Новые проверки используют настоящий HTTP/Gson для повреждённого ответа, настоящий WorkManager для замены retry-цепочки, Room для безопасной отмены отклонённых изменений и Compose для подтверждения/ошибки чтения конфликта. [Что исправлено и как проверяется](review-fixes.md).

## Сквозная проверка через интерфейс

Скрипт использует настоящий установленный APK, `adb`, UI Automator и отдельный HTTP backend с временной SQLite-базой:

```sh
python3 scripts/smoke_android.py \
  --serial emulator-5554 --reset-app --drop-first-response \
  --output build/review-fixes-smoke
```

**Только для выделенного эмулятора:** `--reset-app` удаляет данные пакета `dev.stockflow` на выбранном эмуляторе. Физические устройства скрипт не принимает. Порт компьютера 8080 должен быть свободен. Скрипт временно переключает сеть эмулятора, а затем восстанавливает прежние настройки.

Сценарии:

1. Загрузка заданий через API, ввод нуля и отправка. При флаге `--drop-first-response` сервер фиксирует операцию, но теряет первый ответ; повтор не применяет операцию второй раз. Финальный прогон 5 ноября выполнен с `--drop-first-response`: потерянное подтверждение проверено вместе с остальным UI-сценарием.
2. Ручной ввод штрихкода открывает соответствующий товар.
3. В авиарежиме количество сохраняется. После принудительной остановки и повторного открытия оно остаётся; после возврата сети отправляется в фоне.
4. Изменение другого устройства вызывает конфликт; «Оставить моё» отправляет последнее локальное количество с новой версией и UUID.
5. Повторный конфликт и «Принять серверное» заменяют количество только этого товара. Другой посчитанный товар остаётся без изменений.
6. Запрос разрешения камеры, открытие настоящего CameraX preview и освобождение камеры после закрытия диалога.

Результаты: `status.txt`, скриншоты, UI XML, состояние сервера, дамп активной камеры и SQLite-снимок `backend.sqlite3`. При неудаче сохраняются screenshot и logcat. Сохранённую базу можно использовать для демонстрации того же состояния:

```sh
python3 backend/server.py --database build/review-fixes-smoke/backend.sqlite3
```

Контрольный запуск после исправлений 5 ноября завершился с `PASS`; результаты находятся в `build/review-fixes-smoke/`. Запуск включает `--drop-first-response`. В дампе CameraService зафиксирован активный клиент `dev.stockflow`, после закрытия диалога список активных клиентов пуст. [Скриншоты](screenshots) сохранены в репозитории, включая offline-состояние после перезапуска и оба варианта конфликта. Для продолжения той же демонстрации можно использовать `--database build/review-fixes-smoke/backend.sqlite3`.

## Ограничения проверки

- Физическая камера и разные модели телефонов пока не проверялись. Проверены виртуальная камера эмулятора и распознавание известного изображения реальной библиотекой ML Kit.
- Локальная проверка выполнена на API 36 / arm64. Удалённые Android-тесты подтверждены на API 26 и 36 / x86_64. Это не проверка всех физических устройств.
- В AGP 8.13 K2-анализатор lint падает с `findFirCompiledSymbol`. Включён прежний UAST frontend через `android.lint.useK2Uast=false`; проверки lint не отключались. При обновлении AGP настройку нужно пересмотреть. [Upstream issue](https://issuetracker.google.com/issues/462288595).
- Предупреждения lint включают новые версии библиотек/Gradle, использование kapt, необязательные рекомендации по backup/иконке и KTX. Неиспользуемые строковые ресурсы удалены. Они не скрыты baseline или `abortOnError=false`.
- Debug APK подписан отладочным ключом. Production endpoint, авторизация, публикация в магазине и release-подпись не настроены.
