# Учебный REST backend

Python 3.10+, без внешних зависимостей. Данные, версии и ключи идемпотентности сохраняются в SQLite и переживают перезапуск.

Из корня проекта:

```sh
python3 backend/server.py --database /tmp/stockflow-demo.sqlite3
```

Debug-приложение обращается к `http://10.0.2.2:8080/`: это адрес компьютера внутри стандартного Android Emulator. Нажмите «Загрузить задания» / «Обновить»: появятся два задания и пять товаров. Каталог остаётся доступен после отключения сети.

Для физического устройства:

```sh
adb reverse tcp:8080 tcp:8080
./gradlew installDebug -Pstockflow.debugApiBaseUrl=http://127.0.0.1:8080/
```

HTTP разрешён только debug-приложению. Release endpoint можно задать через `-Pstockflow.releaseApiBaseUrl=https://your-server.example/`; по умолчанию используется нерабочая заглушка `https://stockflow.invalid/`.

## Контракт

- `GET /health`: проверка доступности.
- `GET /api/tasks`: задания с товарами, штрихкодами, учётным и фактическим количеством, версиями.
- `GET /api/items`: диагностический список количеств и число применённых операций.
- `GET /api/items/1`: актуальные `quantity` и `revision` для разрешения конфликта.

Изменение количества:

```http
PUT /api/items/1/quantity
Idempotency-Key: <постоянный UUID операции>
Content-Type: application/json

{"quantity": 12, "baseRevision": 0}
```

Успешный ответ — `200` с подтверждением:

```json
{"quantity": 12, "revision": 1}
```

Сервер сравнивает `baseRevision` с текущей версией и увеличивает версию при записи. Повтор прежнего UUID с теми же товаром, количеством и базовой версией возвращает **первоначальное подтверждение**, не меняя количество и не увеличивая версию ещё раз.

При несовпадении версий — `409`:

```json
{"reason": "revision_conflict", "quantity": 7, "revision": 2}
```

При повторном использовании UUID с другим payload — `409` с `reason: idempotency_conflict`. Клиент различает эти причины: бизнес-конфликт предлагает разрешить пользователю, нарушение ключа приостанавливает очередь без выдуманного серверного значения.

Количество — целое от нуля до `2147483647`, версия — целое от нуля до `9223372036854775806`. Отсутствующий ключ или некорректный payload возвращает `400`, неизвестный товар — `404`. Старые SQLite-файлы backend обновляются автоматически с сохранением количеств и журнала операций. После обновления кода необходимо перезапустить сервер: прежний протокол с `204` больше не используется.

## Конфликт двух устройств

1. Открыть два эмулятора, на обоих загрузить задания: у первого товара версия `0`.
2. На втором устройстве отключить сеть и сохранить `12`.
3. На первом сохранить `7` и дождаться отправки: серверная версия станет `1`.
4. На втором включить сеть и дождаться отправки: появится конфликт с локальным `12` и серверным `7`.
5. «Оставить моё» повторно получает текущую версию сервера, удаляет прежние операции **только этого товара** и создаёт новую операцию с новым UUID. Сервер получает `12`, если версия не изменилась ещё раз.
6. «Принять серверное» получает последнее серверное количество, заменяет локальное и удаляет неотправленные изменения **только этого товара**. Изменения других товаров сохраняются.

Если сервер изменится между получением свежей версии и новой отправкой, клиент снова получит конфликт. Молчаливой принудительной перезаписи нет. Во время конфликта новые изменения этого товара запрещены, а другие товары остаются доступны для локального учёта.

Для проверки без второго устройства можно изменить сервер через `curl`, указав текущую версию из `GET /api/items/1`:

```sh
curl -X PUT http://127.0.0.1:8080/api/items/1/quantity \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: external-device-change-1' \
  -d '{"quantity":7,"baseRevision":0}'
```

Для повторного сценария используйте свежие UUID и актуальную версию либо новый SQLite-файл.

## Воспроизводимые сетевые сбои

Первые две записи получат `503`, затем сервер начнёт принимать изменения:

```sh
python3 backend/server.py --database /tmp/stockflow-demo.sqlite3 --fail-first 2
```

Сервер запишет первую операцию и закроет соединение без ответа. Клиент должен повторить прежние UUID и payload, а `appliedOperations` увеличится только один раз:

```sh
python3 backend/server.py --database /tmp/stockflow-demo.sqlite3 --drop-first-response
```

Для чистого сценария используйте новый SQLite-файл. Старый подтверждённый UUID не считается новой операцией.

## Тесты

```sh
python3 -W error::ResourceWarning -m unittest discover -s backend -v
```

16 тестов проходят без сетевых сокетов: проверяют SQLite и настоящий HTTP handler через потоки байтов. Покрыты каталог, версии, идемпотентность после перезапуска, одновременные дубли и конкурирующие устройства, повторный конфликт во время разрешения, `503`, потерянный ответ и обновление старой базы.

Backend предназначен для локальной разработки. Здесь нет авторизации, TLS, разделения пользователей, распределённого хранения и очистки журнала идемпотентности. Сервер не сбрасывает количество или версии при обычном перезапуске.
